# Contributing to GDriveDatabase

Thank you for your interest in contributing to GDriveDatabase!

We welcome bug fixes, improvements, documentation updates, and new features.

## Getting Started

1. Fork the repository.
2. Clone your fork locally.
3. Create a new branch for your changes.
4. Make your changes and test them thoroughly.
5. Commit your changes with a clear commit message.
6. Open a Pull Request describing your changes.

## Ways to Contribute

### Bug Fixes

* Fix existing issues.
* Improve stability and reliability.
* Add tests when appropriate.

### Improvements

* Improve performance.
* Enhance developer experience.
* Refactor code for better maintainability.

### Documentation

* Improve README examples.
* Add usage guides.
* Fix typos or unclear explanations.

### Features

Before implementing large features, please open an issue to discuss the proposal.

## Code Style

* Follow the existing code style.
* Keep changes focused and easy to review.
* Avoid unnecessary dependencies.
* Write clear and descriptive code.

## Pull Requests

Please ensure:

* The project builds successfully.
* Existing functionality is not broken.
* Documentation is updated when necessary.
* Pull requests have a clear description.

## Reporting Issues

When reporting a bug, include:

* Steps to reproduce
* Expected behavior
* Actual behavior
* Environment details (OS, runtime, version)

## Questions

If you have questions or suggestions, feel free to open an issue.

Thank you for contributing to GDriveDatabase!
